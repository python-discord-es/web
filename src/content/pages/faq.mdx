<Accordion title="¿Cómo instalo Python?">

Descarga el instalador oficial desde [python.org/downloads](https://www.python.org/downloads/)
y elige la última versión estable. Más detalles en la
[documentación oficial](https://docs.python.org/es/3/using/index.html).

- **Windows:** al ejecutar el instalador marca la casilla *Add python.exe to
  PATH*. Luego abre una terminal y comprueba con `python --version` (o
  `py --version`).
- **macOS:** usa el instalador de python.org o [Homebrew](https://brew.sh/)
  (`brew install python`).
- **Linux:** normalmente ya viene instalado. Comprueba con `python3 --version`
  y, si falta, instálalo con el gestor de paquetes de tu distribución.

Para ejecutar un programa guarda tu código en un archivo, por ejemplo
`hola.py`, y ejecuta `python hola.py` (o `python3 hola.py` en Linux y macOS).

</Accordion>

<Accordion title="¿Qué versión de Python debería usar?">

Usa siempre Python 3, preferiblemente la última versión estable. Python 2 dejó
de recibir soporte el 1 de enero de 2020, y los libros, cursos o respuestas
que lo usan (por ejemplo `print "hola"` sin paréntesis) están desactualizados.

</Accordion>

<Accordion title="Me aparece un error enorme, ¿cómo lo leo?">

Python te muestra un *traceback*: la secuencia de llamadas que llevó al error.
Lo más útil está al final:

- La **última línea** indica el tipo de error (`NameError`, `TypeError`,
  `SyntaxError`...) y un mensaje explicativo.
- Las líneas anteriores indican el archivo y el número de línea donde ocurrió.

Lee primero la última línea y luego sube hasta tu propio código. Si pides
ayuda, copia el error completo, no solo la última línea. Más información en
el [tutorial oficial](https://docs.python.org/es/3/tutorial/errors.html).

</Accordion>

<Accordion title="¿Cuál es el mejor editor/IDE para Python?">

Cada persona tiene sus preferencias, experiencia, sistema operativo,
necesidades, etc. Es importante sentirse cómodo con la herramienta que más vas
a utilizar. Por lo tanto, en lugar de basarte en la opinión subjetiva de los
demás (con otras preferencias, experiencias, ...), te resultará mucho más útil
escoger uno o varios (de entre los listados que te damos a continuación)
y probar durante un tiempo cada una. Solo tú puedes contestar a la pregunta.

puede servir de guía para escoger.

En la misma [wiki de Python.org](https://wiki.python.org/) hay un par de
listados exhaustivos sobre editores e IDEs:

- [Editor de texto](https://wiki.python.org/moin/PythonEditors)
- [IDEs](https://wiki.python.org/moin/IntegratedDevelopmentEnvironments)

<Accordion title="¿Qué biblioteca/módulo/framework se recomienda para...?">

Antes de preguntar por una librería o framework puedes echar un vistazo a las
alternativas que hay en el ámbito de tu problema. Un recurso muy interesante
para poder conocer dichas alternativas es
[awesome-python](https://github.com/vinta/awesome-python). Verás que cubre
muchos ámbitos. Hay listas más específicas si tu pregunta trata de
[Django](https://gitlab.com/rosarior/awesome-django),
[Flask](https://github.com/humiaozuzu/awesome-flask)
o [Pyramid](https://github.com/uralbash/awesome-pyramid).

Intenta hacer una pregunta concreta. No es buena idea preguntar ¿qué es mejor
X o Y?. Sin información, la respuesta de cualquier participante será subjetiva.
Matiza cuál es el problema que quieres resolver para que podamos ayudarte en la
recomendación.

<Accordion title="Aplicaciones gráficas (GUI)">

Las principales opciones para crear aplicaciones gráficas en Python son:

* [Tkinter](https://docs.python.org/3/library/tk.html):
  Framework multiplataforma incluido en la biblioteca estándar de Python.
  Basado en [Tcl/Tk](https://www.tcl.tk/). Es la opción más sencilla para
  empezar, ya que no hay que instalar nada.
* [PySide (Qt for Python)](https://doc.qt.io/qtforpython-6/):
  Bindings oficiales de [Qt](https://qt.io), multiplataforma y con licencia
  [LGPL](https://www.gnu.org/licenses/lgpl-3.0.en.html), apta también para
  uso comercial. Diseñador visual: [Qt Creator](https://www.qt.io/ide/).
* [PyQt](https://riverbankcomputing.com/software/pyqt/intro):
  Alternativa muy popular, también basada en Qt. Licencia
  [GNU GPL v3](https://www.gnu.org/licenses/gpl-3.0.en.html) o
  [licencia comercial](https://www.riverbankcomputing.com/commercial/pyqt)
  de pago.
* [wxPython](https://www.wxpython.org/):
  Basado en [wxWidgets](https://www.wxwidgets.org/); los componentes son
  nativos, por lo que la apariencia es igual a la del sistema operativo.
  Diseñador visual: [wxGlade](https://wxglade.sourceforge.net/) o
  [wxFormBuilder](https://github.com/wxFormBuilder/wxFormBuilder).
* [Python GTK](https://pygobject.gnome.org/):
  Bindings de GTK mediante PyGObject, la base del escritorio GNOME. Diseñador
  visual: [Glade](https://glade.gnome.org/).
* [Kivy](https://kivy.org/):
  Framework multiplataforma pensado también para dispositivos táctiles, con
  soporte para Android e iOS. Licencia MIT.
* [Toga](https://beeware.org/project/projects/libraries/toga/):
  Parte del proyecto [BeeWare](https://beeware.org/). Usa widgets nativos de
  cada plataforma, incluyendo móviles.
* [pywebview](https://github.com/r0x0r/pywebview):
  Muestra una interfaz web (HTML, CSS y JavaScript) en una ventana nativa,
  usando el componente webview de cada sistema operativo.

Antes de decidirte revisa que la licencia sea compatible con tu proyecto y que
la biblioteca siga mantenida. Si quieres ver más opciones, puedes leer el
[listado de GUIs](https://docs.python.org/3/faq/gui.html) en la web de Python así como
[herramientas de diseño](https://wiki.python.org/moin/GuiProgramming#GUIDesignToolsandIDEs)
en la wiki de Python.

</Accordion>

<Accordion title="Extraer información de la web">

Básicamente tienes dos opciones:

- Usar [Requests](https://requests.readthedocs.io/) para el acceso y
  [BeautifulSoup](https://www.crummy.com/software/BeautifulSoup/bs4/doc/)
  para la extracción.
- Usar el framework [Scrapy](https://scrapy.org/).

Si la página genera su contenido con JavaScript, necesitarás automatizar un
navegador con [Playwright](https://playwright.dev/python/) o
[Selenium](https://www.selenium.dev/).

También puede resultarte de ayuda el libro
[Automate the boring stuff](https://automatetheboringstuff.com/), que incluye
un capítulo sobre web scraping (en inglés).

Antes de extraer datos de un sitio, revisa sus términos de uso y su
`robots.txt`.

</Accordion>

<Accordion title="Instale un módulo y no funciona ¿Cómo se resuelve?">

Esta pregunta suele ser muy frecuente en distintas plataformas, y lo más
importante es saber como está configurado nuestro entorno y proyecto.

¿Creaste un entorno virtual para tu proyecto?

- Sí, entonces verifica que tu IDE (PyCharm, VScode, etc) utiliza el ejecutable
  `python` de ese entorno virtual.
- No, verifica que al escribir `pip` sea el correspondiente a tu intérprete de
  Python en uso.

En Linux y macOS puedes clarificar esto ejecutando el comando `which python`
o `which pip` en tu terminal.
En Windows, puedes ejecutar el comando `where` para verificarlo de la misma
forma.

Te recomendamos nunca instalar módulos con `pip install ...` sin haber
creado un entorno virtual. Esto es principalmente para que no instales
módulos en tu sistema o cuenta de usuario que vayan a chocar con tu
configuración de cada proyecto.

Solo crear un nuevo entorno con `python -m venv nombre`
(donde `nombre` es el nombre que quieras para tu entorno),
y luego para activarlo:

- En Linux y macOS, `source nombre/bin/activate`,
- En Windows, `nombre\Scripts\activate`.

Más detalles en la [documentación de venv](https://docs.python.org/es/3/library/venv.html).
Si prefieres una herramienta moderna que gestiona entornos y dependencias por
ti, puedes probar [uv](https://docs.astral.sh/uv/).

</Accordion>

<Accordion title="¿Qué es uv? ¿Tengo que usarlo en lugar de pip?">

[uv](https://docs.astral.sh/uv/) es una herramienta más nueva para instalar
paquetes y gestionar entornos virtuales y versiones de Python. Puede usarse en
lugar de `pip` y `venv`, y suele ser bastante más rápida.

**No es obligatorio.** `pip` y `venv` siguen siendo la forma estándar, vienen
con Python y son lo que explican la mayoría de los cursos y libros, así que
puedes seguir usándolos con normalidad. Elige la que te resulte más cómoda:

- Con pip: `python -m venv nombre` y luego `pip install paquete`.
- Con uv: `uv venv` y luego `uv pip install paquete`, o `uv add paquete` si
  usas un proyecto con `pyproject.toml`.

Lo importante en ambos casos es lo mismo: usar un entorno virtual por
proyecto.

</Accordion>
